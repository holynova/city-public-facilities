近邻 GEO 页面诊断与优化报告

审计日期：2026 年 8 月 23 日
目标站点：近邻城市公共设施近邻检索
目标读者：项目维护者、前端开发者、内容维护者
状态边界：线上基线已实测；优化结果为本地已实现、尚未部署

1. 执行摘要

近邻的核心功能可以正常使用，首页和功能介绍页在线均返回 HTTP 200，桌面与移动端渲染后可读取城市目录和设施数量。但上线前基线存在三个会直接影响发现、抽取和引用准备度的问题：robots.txt 与 sitemap.xml 返回 404；首页缺少 description、canonical 和结构化数据；首页城市覆盖、数据方法和责任边界大多不在初始 HTML 中。

本次已在本地完成 P0/P1 整改：增加 robots 与 sitemap；为首页和功能介绍页补齐唯一标题、描述、canonical、社交元数据和与正文一致的 JSON-LD；把 14 个城市、28,588 处地点、GCJ-02、直线距离、每类最近三处、手动更新和核验边界写入初始 HTML；补充数据方法、FAQ、维护日期和 GitHub 纠错入口。

这些改动提升的是公开页面被发现、解析和引用的准备度，不代表任何 AI 平台已经召回、引用或提高排名。没有搜索日志、Search Console 数据或 AI 平台重复采样，因此本报告不提供抓取频次、平台排名、提及率或引用份额结论。

2. 输入、范围与边界

  • 项目实体：近邻（City Public Facilities），公开源代码城市公共设施近邻检索工具。
  • 目标问题：近邻是什么、支持哪些城市、数据来自哪里、如何计算最近地点、数据是否实时、结果是否为官方结论。
  • 可用证据：线上 HTTP、线上渲染页面、本地 HTML/CSS/JavaScript、公开 GitHub 仓库、数据 JSON、技术标准和研究资料。
  • 输入缺口：无服务器访问日志、无 Search Console、无 AI 平台采样、无统一的数据发布日期字段、无每条设施的页面级来源链接。
  • 竞争范围：本次为单站技术与内容整改，不做竞品排名或平台表现推断。

7. 抓取与渲染

7.1 HTTP 与发现

  • 观察：首页与 about 返回 200，GitHub Pages 提供稳定静态 HTML。
  • 观察：上线前 robots 和 sitemap 返回 404。
  • 已实施：新增允许抓取的 robots 文件，并指向 sitemap。
  • 已实施：sitemap 收录首页和 about，并写入本次修订日期。
  • 已实施：两个页面均在初始 HTML 中声明唯一 canonical。

7.2 初始 HTML 与渲染 DOM

上线前首页初始 HTML 有主标题和操作控件，但城市选项由 JavaScript 生成，设施数量和结果状态需要加载 JSON 后才出现。浏览器渲染后可见上海 2,790 处地点和 14 个城市，说明功能链路正常，却也证明“用户可见”与“初始 HTML 可读”并不相同。

本地整改后，首页预渲染全部 14 个城市选项和核心事实；about 预渲染 14 行城市数量，JavaScript 仍会在加载成功后使用当前 JSON 更新这些值。这样既保留现有功能，也为不能执行 JavaScript 的抓取器提供稳定正文。

7.3 验收方式

请求首页、about、robots 和 sitemap，确认状态码。
禁用 JavaScript 后打开首页，确认城市和方法仍可阅读。
启用 JavaScript 后确认城市切换和设施目录加载不受影响。

8. 移动端、性能与可访问结构

移动端浏览器基线显示：首页与 about 的导航、标题、统计和城市列表可正常呈现；页面采用响应式窄栏布局。现有 main、标题层级、表单 label、导航 aria-label 和 about 跳转链接为良好基础。

本次新增内容继续使用语义化 section、definition list、article、details/summary 和 time 元素。未引入新的图片、字体或运行时框架，因此额外网络成本主要为少量 HTML 字节。后续性能验收应在部署后使用真实 URL 复测 LCP、INP 和 CLS；本报告不以本地静态检查替代现场指标。

9. 结构规范性

  • 首页维持一个 H1，新增“近邻是什么”H2，并保留“最近地点”H2。
  • about 维持一个 H1，新增“数据方法与使用边界”“常见问题”“维护与责任”等清晰 H2。
  • 城市清单使用有序列表；数据方法使用 article；FAQ 使用原生 details/summary。
  • 首页到数据方法使用可抓取的普通链接，不使用 hash 路由生成独立内容。
  • 当前没有面包屑可见组件；about 的 JSON-LD 只声明两级路径。若新增城市详情页，应同步增加可见面包屑。

10. 内容证据与责任边界

本次把以下事实改造成上下文独立、可单独引用的句子：

  • 近邻是城市公共设施近邻检索工具。
  • 当前发布快照覆盖 14 个城市和 28,588 处地点。
  • 地址解析依赖高德地图；距离使用 GCJ-02 坐标计算。
  • 距离是球面直线距离，不是步行或驾车路线距离。
  • 每个细分类别默认展示最近三处地点。
  • 设施目录按需人工更新，不是实时数据库。
  • 医院等级、学校属性、开放时间等必须向主管部门或场所官方渠道复核。

数据 JSON 当前没有生成时间、来源 URL、来源类型或单条记录的核验日期。本次没有伪造这些字段。建议后续在导出 schema 中增加数据级 generatedAt，并逐步为高风险分类增加 sourceName、sourceUrl、verifiedAt 和 verificationStatus。

11. AI 可抽取性

上线前可抽取性风险主要来自关键事实依赖 JS、说明分散和缺少问答结构。本次在首页增加四张事实卡，在 about 增加数据方法和五个 FAQ，使定义、步骤、限制、更新方式和纠错路径能够作为独立 chunk 被读取。

JSON-LD 采用 WebSite、WebApplication、AboutPage、BreadcrumbList、Question 和 Answer 类型，并通过稳定的 @id 关联页面实体。所有 schema 事实都能在可见正文中回溯。schema 的作用是辅助实体与页面关系解析，不替代正文，也不保证富结果或生成式引擎引用。

13. P0/P1 修复清单

P0-1：缺少 robots 与 sitemap

  • 问题：两个发现入口在线返回 404。
  • 证据：2026-08-23 对公开 URL 的 HTTP 实测。
  • 影响：抓取器缺少站点级许可说明和规范页面清单。
  • 修复动作：新增 robots.txt 和 sitemap.xml，sitemap 只列出可索引 HTML 页面。
  • 负责人：前端/仓库维护者。
  • 成本：S，小于 0.5 人日。
  • 验收：部署后两个 URL 返回 200，sitemap XML 可解析且页面 URL 返回 200。

P0-2：首页核心事实依赖 JavaScript

  • 问题：上线前城市选项为空，目录数量与方法信息未写入初始 HTML。
  • 证据：首页基线正文约 193 字；浏览器渲染后才出现 14 个城市和上海 2,790 处地点。
  • 影响：不运行 JavaScript 的抓取器难以获得完整实体、覆盖和使用边界。
  • 修复动作：预渲染城市选项、项目定义、覆盖规模、计算方式、返回规则与核验边界。
  • 负责人：前端开发者。
  • 成本：S，约 0.5 人日。
  • 验收：禁用 JavaScript 后仍能读取上述事实；启用后查询功能不回归。

P1-1：页面元信息和实体关系不足

  • 问题：首页缺 description、canonical、社交元数据和 JSON-LD；about 缺 canonical 与 JSON-LD。
  • 证据：上线前源代码检查。
  • 影响：页面主题、规范 URL 和实体关系表达不足。
  • 修复动作：为两个页面增加独立 metadata；以稳定 @id 关联 WebSite、WebApplication 和 AboutPage。
  • 负责人：前端开发者。
  • 成本：S，小于 0.5 人日。
  • 验收：HTML 解析检查通过；JSON-LD 可解析；schema 事实均可在正文回溯。

P1-2：数据更新与责任说明不完整

  • 问题：基线使用“实时读取已发布目录”，容易被理解为实时设施数据。
  • 证据：about 基线文案与项目当前人工更新策略。
  • 影响：可能导致用户或生成式系统误述数据实时性和权威性。
  • 修复动作：改为“读取当前发布的数据快照”，新增手动更新、核验边界、维护日期与 Issue 入口。
  • 负责人：内容维护者。
  • 成本：S，小于 0.5 人日。
  • 验收：页面明确写出非实时、直线距离、非官方资格证明和纠错方式。
